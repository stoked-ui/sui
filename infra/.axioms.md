# Infra Axioms

- `cdn.stokd.cloud/<directory>/?f=json|yaml` is a stable public directory-listing API and must resolve to that directory, not bucket root.
- CDN edge logic must preserve the path-based API contract without requiring callers to know about internal `prefix=` query parameters.
- Do not rewrite public CDN listing requests in a way that depends on non-API cache behaviors forwarding injected query strings.

## AX-INFRA-HOST-MANIFEST-ROUTING — Canonical And Vanity Hosts Share One Routing Manifest

**Why:** To ensure deterministic, auditable AWS infrastructure deployment where canonical domains (`.stokd.cloud`) and their vanity counterparts (`stoked-ui.com`, `stokedconsulting.com`, `brianstoker.com`) are treated as equal routing peers, sharing certificates, DNS validation, and CloudFront aliases from a single source of truth.

**How to apply:**
1. Export `PRODUCTION_HOST_MANIFEST` from `infra/domains.ts` with the exact shape tested in `infra/domains.test.ts`.
2. Group hosts by logical service: `suiConsultingDistribution` (SUI + consulting sites), `brianDistribution` (Brian's personal site), `cdnDistribution` (CDN endpoints).
3. Within each group, separate `canonicalRoots` (`.stokd.cloud`) from `vanityRoots` (public registrable apexes) but present both in `requiredHosts` for certificate coverage.
4. Preserve existing mail/verification records (MX, TXT) that are unrelated to the routing manifest.
5. Drive all AWS alias, certificate, and DNS validation from the manifest's `zoneMap` and `requiredHosts` arrays.

**Acceptance Checks:**
- **Test:** `pnpm exec cross-env NODE_ENV=test mocha infra/domains.test.ts --reporter spec` passes.
- **AWS CloudFront:** All `requiredHosts` appear as CloudFront distribution aliases.
- **AWS Route53:** Each apex domain (`stokd.cloud`, `stoked-ui.com`, `stokedconsulting.com`, `brianstoker.com`) resolves to its correct hosted zone ID from the `zoneMap`.
- **Certificate:** ACM certificates cover every `requiredHost` (both apex and `www.` subdomains).
- **DNS/Alias validation:** All vanity domains must use alias records pointing to CloudFront distributions with matching HTTPS certificates.

**Concrete validation commands:**
```bash
# Verify hosted zones match exact zone IDs
AWS_PROFILE=stokd-cloud AWS_DEFAULT_PROFILE=stokd-cloud aws route53 list-hosted-zones \
  | jq '.HostedZones[] | select(.Name | test("(stokd\\.cloud|stoked-ui\\.com|stokedconsulting\\.com|brianstoker\\.com)$")) | {Name, Id}'

# Verify CloudFront distribution aliases with executable assertions
# SUI/consulting distribution (E1GT1O1IPEPT2W) must have EXACT aliases: consulting.stokd.cloud, stoked-ui.com, stokedconsulting.com, sui.stokd.cloud, www.consulting.stokd.cloud, www.stoked-ui.com, www.stokedconsulting.com, www.sui.stokd.cloud
AWS_PROFILE=stokd-cloud AWS_DEFAULT_PROFILE=stokd-cloud aws cloudfront get-distribution --id E1GT1O1IPEPT2W \
  | jq -e '.Distribution.DistributionConfig.Aliases.Items | sort' \
  | jq -e '.[0] == "consulting.stokd.cloud" and .[1] == "stoked-ui.com" and .[2] == "stokedconsulting.com" and .[3] == "sui.stokd.cloud" and .[4] == "www.consulting.stokd.cloud" and .[5] == "www.stoked-ui.com" and .[6] == "www.stokedconsulting.com" and .[7] == "www.sui.stokd.cloud"'

# Brian distribution (E1JN9JWBQ37JT2) must have EXACT aliases: brian.stokd.cloud, www.brian.stokd.cloud, brianstoker.com, www.brianstoker.com

# CDN distribution (E3PC4DOJ0WYY7L) must have EXACT aliases: cdn.stokd.cloud, cdn.stokedconsulting.com
AWS_PROFILE=stokd-cloud AWS_DEFAULT_PROFILE=stokd-cloud aws cloudfront get-distribution --id E3PC4DOJ0WYY7L \

AWS_PROFILE=stokd-cloud AWS_DEFAULT_PROFILE=stokd-cloud aws acm describe-certificate \

AWS_PROFILE=stokd-cloud AWS_DEFAULT_PROFILE=stokd-cloud aws acm describe-certificate \

# Verify HTTPS access for all canonical and vanity hosts
for host in \
  sui.stokd.cloud www.sui.stokd.cloud \
  consulting.stokd.cloud www.consulting.stokd.cloud \
  brian.stokd.cloud www.brian.stokd.cloud \
  cdn.stokd.cloud \
  stoked-ui.com www.stoked-ui.com \
  stokedconsulting.com www.stokedconsulting.com \
  brianstoker.com www.brianstoker.com \
  cdn.stokedconsulting.com; do
  echo "Checking https://$host ..."
  curl -sf -o /dev/null --max-time 5 https://$host || {
    echo "FAILED: https://$host unreachable"
    exit 1
  }
done
echo "All hosts respond successfully over HTTPS"
```
